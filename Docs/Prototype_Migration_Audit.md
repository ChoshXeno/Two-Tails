# 灰盒机制迁移审查

已验收玩法以用户交接为基线。当前完整入口是 Windows Friends Test → Prototype_MainMenu → Local Play → Prototype_SplitScreen，或 Online Play → Prototype_OnlineTest。Windows、Windows Network Prototype 和 iOS Prototype 配置仍分别指向早期 Greybox 或 Network 场景，不能用来证明最新机制可用。下列判断来自代码和实际序列化引用，实测范围见文末。

[Inspector 实测值与引用清单](Prototype_Inspector_Inventory.md)按场景和 Prefab 列出组件、实际字段和值。下表列的是迁移时最常用或必填的字段。清单里的空值要结合运行时绑定及机制类型判断。

距离、相机遮挡和灯光遮挡是三次独立判断。夜间 shader 先计算以角色为中心的距离，再计算场景照明。墙体首先通过正常深度测试挡住镜头后的物品，相机防穿墙另由 FollowCamera 的遮挡层控制。只有显式配置的 revealBarriers 会挡近身显现。远处发光球由 GuideLight 根据开启的 Point/Spot 灯生成，球体使用正常深度测试。实体远处可见例外取自 URP additional lights 的衰减，月光只负责照明。夜间默认压制局部灯阴影，因此光池在墙背可能仍显现，尽管发光球本身被挡住。月光保留主灯阴影，屋檐依赖实体几何与 ShadowCaster。透明文字、水和坝轮廓继续服从距离规则。

安全整理只删除了全项目无调用的 shader 帮助函数。两张主场景的测试区已按根节点分组。多个 DoorPanel、Plate A/B、Visual 名称在各自父节点下有独立引用。保留层级和对象名能避免影响运行时 Find、局部坐标及 NGO 场景身份。三个 Probe 脚本用于开发验证，Editor Setup/Builder 用于生成测试资产，正式场景无需调用。优先拆出 AnimalMechanicsWorld 的换角、坝、课程职责及复位锚点，其次把相机和 Lever 的全场景查找改成显式绑定，并把 NightEnvironment 的全场景材质转换限制在指定关卡根下。现有 prefab 和 Hierarchy 没有重存。

Unity Edit Mode 使用 Preview Scene 检查五张场景和两个玩家 Prefab。每个资产均为零 Missing Script、零已序列化但断开的 Prototype 对象引用、零同 GameObject 重复 MonoBehaviour 类型。SplitScreen Play Mode 实测左右各半幅，绑定 Fox 和 Monkey。将现有 Swimming Pool 根复制到无资产的临时运行时场景后，水位从 -0.6 更新到 -2，Safe Shore 引用仍可读；临时场景随退出 Play 清理。这个实验覆盖水域配置与引用迁移，原分屏 Manager 仍在同一进程，且没有测试角色入水或独立关卡启动。独立 Host/Client、Relay、实际手控、渲染画面与整套机关回归未重跑。
